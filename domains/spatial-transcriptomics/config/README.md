# Configuration Guide

## Overview

The `config/` directory holds two types of configuration files:

| File | Tracked in git? | Purpose |
|------|----------------|---------|
| `slurm_config.sh.example` | **Yes** | Template with placeholder values — commit-safe |
| `slurm_config.sh` | **No** (gitignored) | Your actual values — keep this local |
| `hpc_profile.sh.example` | **Yes** | HPC module name overrides template |
| `hpc_profile.sh` | **No** (gitignored) | Your actual module names — keep this local |
| `capabilities.sh` | **No** (gitignored) | Auto-generated by `setup.sh` — records which execution modes (container / native) are available for each feature. Re-generate at any time with `bash setup.sh`. |

---

## Quick Start: SLURM Configuration

**One-time setup** (do this right after cloning):

```bash
cp config/slurm_config.sh.example config/slurm_config.sh
```

Then edit `config/slurm_config.sh` and fill in your HPC account and partition:

```bash
export SLURM_ACCOUNT="your-account"   # e.g., pi-yourlab
export SLURM_PARTITION="your-partition"  # e.g., caslake, gpu, etc.
```

Once populated, `run_benchmark.sh` and `run_pipeline.sh` will read these values
automatically — you won't need to pass `--account` / `--partition` on the command
line every time.

**To find your account and partition**, check with your HPC admin or run:
```bash
sacctmgr show user $USER withassoc format=account,partition
```

## Quick Start: HPC Module Names

If your cluster uses non-standard module names for Singularity, Julia, or Python,
copy and edit the HPC profile:

```bash
cp config/hpc_profile.sh.example config/hpc_profile.sh
```

Edit `hpc_profile.sh` to set the correct module names for your cluster.
`setup.sh` and the orchestration scripts source this file automatically.

---

## What Goes Here vs. What Stays in Your Head

- `config/slurm_config.sh` — SLURM account, partition, optional defaults (memory, time, email)
- `config/hpc_profile.sh` — Module names specific to your HPC system
- Everything else (dataset paths, output directories, SVD parameters) — passed as
  command-line arguments to `run_pipeline.sh` / `run_benchmark.sh`, or configured
  at the top of `docs/run_locally.sh` for local runs
